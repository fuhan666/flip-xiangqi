# Flip Xiangqi

翻牌中国象棋本地双人对局。

当前版本：**0.8.0**（局域网实时走棋对战、快捷短语互动与棋谱记录底座版本，详见 [Changelog](CHANGELOG.md)）。

项目基于标准中国象棋规则，加入“将/帅固定明置，其余 30 枚棋子全局随机暗置、翻牌算一步”的变体玩法。棋盘以标准 9×10 网格做纯 2D DOM 渲染，点击格子完成翻牌与走子。

当前版本已经覆盖：

- Phase 1：项目骨架、规则数据模型、纯规则引擎边界
- Phase 2：随机暗置开局、翻牌动作、回合切换
- Phase 3：全部棋种的标准走法、暗子阻挡、不可直接吃暗子、炮架判定
- Phase 4：将军判定、照将限制、非法自杀着拦截、终局结算
- Phase 5：本地双人交互界面、状态提示、吃子区、重新开局
- 纯 2D 棋盘渲染：标准 9×10 网格、语义化交互按钮与无障碍标签
- 古典视觉呈现：木纹质感棋盘与实木圆形棋子、楚河汉界与九宫斜线、棋位角标、楷体书法棋面（红方帅仕相俥傌炮兵，黑方将士象車馬砲卒）
- 局域网联机大厅与保活底座：内置 WebSocket 宿主、一键建房与多网卡地址分享、客人浏览器直连加入、大厅设置同步（分先与局时）、双端就绪门禁、冻结开局参数快照、3 秒心跳健康监测与 RTT 状态灯、5 秒静默断线感知、断线横幅与重连恢复（详见 [局域网联机搭建指南](docs/lan-setup.md)）
- 局域网实时走棋对战与权威计时：双方视角自适应（己方棋子均居下方操作）、服务端权威局时/步时与 1Hz 广播平滑走秒、局时紧迫脉动与步时逐秒闪烁、1.5 秒将军警示条、90 秒断线宽限期与冻结恢复、权威终局判定与结算弹层（绝杀/吃将/超时判负、双方耗时统计与胜方轻微庆祝动效）及「再来一局」/「返回大厅」流转
- 局内内置快捷短语互动：12 条精选中文预置短语（问候/赞赏/思考/礼仪）、5 秒权威共享频控倒计时、3 秒浮动气泡平滑淡出，支持 Esc 收起与 reduced-motion 降级
- 悔棋/认输/求和协商流：双向 30 秒应答倒计时弹窗、行棋互斥锁定、悔棋单步回滚与时钟恢复、求和 10 秒冷却与认输结算
- 棋谱记录基础设施（为 v0.9 铺路）：连续 stepNumber 步数、flip/move/capture 动作分类、吃子快照、权威思考时间 durationSeconds 注入及独立的 matchEvents 协商留痕轨迹

## 本地运行

```bash
npm install
npm run dev
```

`npm run dev` 启动本地宿主进程（开发形态：Vite middleware + 热更新），终端会打印本机控制台地址，浏览器打开即可开始对局。控制台默认监听 `127.0.0.1:5173`，只对本机可见。

生产形态需要先构建再启动：

```bash
npm run build
npm start -- --port 4173
```

两种形态都由同一个 Node 宿主承载：控制台页面（本机）加上按需启动的局域网房间服务（建房后才监听）。

宿主参数（命令行与环境变量同义）：

| 参数 | 环境变量 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `--port` | `UI_PORT` | 开发 `5173` / 生产 `4173` | 本机控制台页面端口 |
| `--room-port` | `ROOM_PORT` | `8080` | 建房时在局域网监听的优先端口 |

也可以在界面「设置」里配置建房优先端口。

## 局域网建房与对战

当前版本提供**完整的局域网联机对战闭环**：完成建房 → 分享地址 → 客人加入 → 大厅设置与就绪 → 服务端权威局时/步时对战 → 90 秒断线宽限保护 → 终局胜负结算与再局/回厅流转（详见 [局域网联机搭建指南](docs/lan-setup.md)）。同时继续完整保留同机本地双人对战模式。

房主：

1. 打开控制台，点「创建房间」。
2. 界面展示 `IP:端口` 连接卡片，一键复制后发给对手；多网卡时可展开候选地址列表选择。
3. 默认端口被占用时会自动顺延，并如实展示真正监听成功的端口。
4. 「关闭房间」需二次确认，已加入的客人会收到明确通知。

客人（无需安装 Node，只用浏览器）：

- 直接访问房主分享的 `http://IP:端口`，页面里点「加入房间」；
- 或在自己已打开的客户端里输入 `IP:端口` 加入（支持省略 `http://`、首尾空格）。
- 加入成功的地址会保存到「最近房间」（本地保存最近 5 条），点击即可重新填入连接。

连接失败时会给出具体、可行动的提示（地址格式缺端口、连接超时/被拒绝、房间已满、协议版本不符等分别对应不同文案）。

### 连不上时的排查

- **同一网段**：两台设备必须连接同一个 Wi-Fi / 局域网，不同 VLAN、访客网络或 AP 隔离会互相不可见。
- **防火墙**：首次启动 Node 时在系统弹窗中选择「允许」；Windows 需放行入站连接，macOS 可在「系统设置 → 网络 → 防火墙」中放行 Node。
- **地址选对**：多网卡机器上换用「候选地址列表」里的其它网卡地址（有线/无线常常不同）。
- **端口被占用**：默认端口被占时界面会自动顺延，以界面上显示的实际端口为准；也可在「设置」或 `ROOM_PORT` 中自选端口。
- **仅有回环地址**：若界面标注的是仅供本机测试的 loopback 地址，说明当前没有可用局域网地址，客人无法从其它设备加入。

连接层协议（消息封包、握手、错误码）定义在 `src/network/protocol.ts`，宿主实现在 `server/`，两端共享同一套校验。

## 测试与构建

```bash
npm test
npm run build
```

构建产物包含前端静态资源与 Node 宿主（`dist/` + `dist-server/`），不包含 3D 相关依赖、拆包清单或特调的 chunk 警告阈值。

浏览器冒烟、视觉检查与全流程对局回归（需先 `npm run build`）：

```bash
npm run test:e2e   # 等价于 npx playwright test
```

视觉套件覆盖多分辨率棋盘几何、暗子脱敏等价、reduced-motion、交互流程与字体渲染取证；`e2e/game-flow.e2e.ts` 以固定种子随机开局，用合法点击序列覆盖 翻牌 → 己方走子 → 暗子阻挡/非法操作 → 吃子 → 炮翻山吃子 → 真实将死 → 重开 全链路。`e2e/room-connection.e2e.ts` 用隔离浏览器上下文真实走通建房 → 加入 → 成员互见、满员、离开后席位复用、房主关闭房间与最近房间持久化。`e2e/audio-feedback.e2e.ts` 在 Web Audio 边界观测真实调度，校验翻牌/落子/吃子/终局音效的合成路径、非法操作静音、音量与静音即时生效并跨刷新保持，以及联机双端各自本地播放与断线恢复不补播。截图输出到仓库外的 `evidence/` 目录。

## 交互说明

- 点击暗子：翻牌，消耗整回合
- 点击己方明子，再点击目标格：尝试移动/吃子
- 选中己方明子后，棋盘会标注全部合法落点：空位显示光圈，可吃明子显示外围环（暗子与己方子不会被标注）
- 走子时显示起止点连线轨迹，棋盘持久保留“最后一步”起止高亮环，悔棋后自动恢复
- 吃子时被吃棋子以残影退场，己方将/帅被将军时棋盘外框显示警示波纹与将军警示条
- 关键动作配有原生合成音效：翻牌清脆短促、落子厚重木质敲击、吃子破碎爆鸣、将军柔和警示、终局胜利短乐句；侧栏「音效」面板可随时拖动音量或一键静音，改动即时生效
- 非法着法会在右侧状态面板显示原因，且不会发出任何音效
- 对局结束后可点击“重新随机开局”或“再来一局”开始下一局

## 体验边界

- 棋盘主区域为纯 2D 渲染（DOM 按钮 + SVG 装饰层，无 3D 场景），保持 9:10 等比缩放、不失真
- 暗子翻开采用 360ms 立体 Y 轴翻转动效，翻转前半程全界面（棋盘、旁栏、历史）严格隐藏棋子身份，过半后才揭示
- 全部动效遵循 `prefers-reduced-motion: reduce`：开启后直接呈现最终状态，无翻转、呼吸、轨迹与波纹动画
- 暗子统一为祥云暗纹木背，未翻开前带轻微呼吸/悬浮动效；`prefers-reduced-motion` 下自动停用
- 暗子翻开前不渲染任何正面棋子信息，仅显示占位「暗」标记
- 联机现已完整支持局域网实时网络走棋、翻牌与协商对战；同机本地双人对战继续完备保留
- 音效全部由 Web Audio API 实时合成（振荡器 + 噪声 + 增益包络 + 软限幅），仓库不含任何音频资源文件，也不依赖外部音频服务
- 音量滑杆与全局静音开关保存在本机浏览器（localStorage），刷新与重开后保持；联机对战中双端各自本地播放，本机设置不影响对方
- 受浏览器自动播放策略限制，AudioContext 只在首个用户手势后创建或恢复；进入页面后尚未产生任何点击前到达的音效会被直接丢弃，不会延迟补播
- 不包含 AI、账号体系与公网部署，联网范围仅限局域网，不依赖任何外部服务
