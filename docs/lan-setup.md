# 局域网联机搭建指南

本文档介绍如何在局域网（Wi-Fi 或有线网络）环境下搭建并使用翻牌中国象棋的联机大厅。

> **当前阶段能力说明**：v0.7.0 交付的是**局域网联机大厅底座与稳定性闭环**（建房、地址分享、客人直连、大厅设置同步、双端就绪门禁、心跳健康监测、断线恢复及不可变开局参数快照）。点击「开始对局」后，双方将生成并冻结开局参数快照（分先归属与局时设置）；联机实时走棋对战属于后续规划范围，当前实际走子对局仍为本地双人运行。

---

## 1. 运行前提

- **房主设备**：需要安装 Node.js（推荐 Node.js v18 及以上，已在 v24.x 验证通过）及 npm。
- **客人设备**：**无需安装 Node 或任何开发环境**，只需具备现代桌面或移动端浏览器（Chrome、Edge、Safari、Firefox 等）。
- **网络环境**：两台设备必须连接到同一个局域网（如连接同一个家庭/办公室 Wi-Fi 路由器，或同一台交换机）。

---

## 2. 启动服务（房主）

### 2.1 开发形态启动

适用于代码调试或快速试玩，内置 Vite 模块热更新：

```bash
npm install
npm run dev
```

终端将打印房主控制台地址（默认 `http://127.0.0.1:5173/`）。

### 2.2 生产形态启动（推荐）

经过完整打包构建，响应更轻量稳定：

```bash
npm run build
npm start -- --port 4173
```

终端将打印房主控制台地址（默认 `http://127.0.0.1:4173/`）。

## 3. 端口与网络架构说明

翻牌中国象棋采用安全分层的网络设计：

```
+-------------------------------------------------------------+
| 房主设备 (Host)                                             |
|                                                             |
|  [房主浏览器] ----(仅回环 loopback)----> [Node 控制台进程]   |
|                                           (5173 / 4173)     |
|                                                 |           |
|                                           [按需启动房间服务] |
|                                           (默认 8080 端口)   |
|                                                 |           |
+-------------------------------------------------|-----------+
                                                  |
                                                  | 局域网 HTTP + WebSocket (/ws)
                                                  v
                                      +-----------------------+
                                      | 客人设备 (Guest)       |
                                      | [客人普通浏览器]       |
                                      +-----------------------+
```

### 3.1 房主控制台端口（Loopback）
- **开发端口**：`5173`
- **生产端口**：`4173`
- **安全约束**：控制台仅绑定在 `127.0.0.1`（本机回环接口），不向局域网暴露控制 API，杜绝外部未经授权的房间管理操作。

### 3.2 局域网房间端口（Room Port）
- **默认端口**：`8080`
- **按需监听**：房主在控制台点击「创建房间」后，Node 服务才会真正监听该端口；解散房间后端口立即释放。
- **自动顺延策略**：若 `8080` 端口被其他软件占用，服务会自动尝试 `8081`、`8082` 等顺延端口（最多尝试 20 个端口），直到找到可用端口或耗尽尝试；控制台界面会如实展示当前真正监听的端口号。
- **单端口复用**：客人通过同一个房间端口访问：
  - HTTP 页面：`http://<房主IP>:<房间端口>/`
  - WebSocket 握手：`ws://<房主IP>:<房间端口>/ws`
  无需为 WebSocket 额外开放第二端口。

### 3.3 端口配置方式
房主可通过三种等价方式自定义建房优先端口：
1. **界面配置**：在主菜单「设置」中填写优先端口（1–65535）并保存，本地浏览器会自动记忆。
2. **命令行参数**：启动时指定 `--room-port <端口号>`，例如 `npm start -- --room-port 9000`。
3. **环境变量**：通过 `ROOM_PORT=<端口号>` 指定，例如 `ROOM_PORT=9000 npm run dev`。

## 4. 建房与客人加入流程

### 4.1 房主操作
1. 本机浏览器打开控制台（`http://127.0.0.1:4173/` 或 `5173`）。
2. 点击「创建房间」。
3. 界面会显示当前房间的专属连接卡片（格式为 `IP:端口`）：
   - 点击「复制」按钮复制连接地址。
   - 若房主机器有多个网卡（例如同时开启了 Wi-Fi、有线以太网或虚拟网卡），可展开「候选地址列表」，选择与客人处于同一网段的局域网 IP。
4. 将复制的地址发送给对手。

### 4.2 客人操作
客人只需使用浏览器，任选以下一种方式进入：
- **方式 A（直链访问）**：在浏览器地址栏直接输入房主分享的 `http://<IP>:<端口>`，页面加载后点「加入房间」即可。
- **方式 B（输入框填入）**：打开已有客户端页面，点击「加入房间」，输入房主提供的 `IP:端口`（支持自动去除首尾空格及自动补全 `http://`），点击「连接」。
- 加入成功后，该地址会自动加入客人的「最近房间」列表（本地保存最多 5 条），后续可一键快捷填入。

## 5. 大厅交互与开局状态流转

1. **设置同步**：
   - 房主可调整「分先策略」（随机抽签、房主执红、客人执红）与「局时模式」（不计时、快棋 10 分+30 秒、标准局 20 分+60 秒、慢棋 30 分+90 秒）。
   - 客人端实时同步显示设置变更，客人端设置区域保持只读，确保房间规则权威统一。
   - 房主可点击「锁定设置」防止意外误触，锁定期间不可调整参数。
2. **双端就绪门禁**：
   - 双方需各自点击「准备」按钮。
   - 任何一方修改设置或解锁设置，系统会自动重置双方的就绪状态，防止规则不一致下的抢跑。
   - 仅在双方均处于「已准备」状态时，房主的「开始对局」按钮才会点亮。未就绪时点击将被拦截并提示。
3. **冻结开局快照**：
   - 房主点击「开始对局」后，房间状态流转为已开局，大厅设置与操作入口冻结。
   - 若设置了随机分先，服务端在此刻权威抽取红黑归属（不可重复抽取），生成不可变开局参数快照（含设置版本、红黑归属及局时规则）。
   - 双端界面同步呈现快照信息，确保开局状态一致可信。

## 6. 网络状态监控与断线恢复

### 6.1 实时心跳与状态指示灯
- 双端通过 WebSocket 建立 3 秒一次的双向心跳探测（`ping` / `pong`），实时测算往返时延（RTT）。
- 顶部导航栏展示网络状态指示灯与 RTT 数值：
  - **绿色（良好）**：RTT ≤ 80ms
  - **黄色（较高延迟）**：80ms < RTT < 200ms
  - **红色（高延迟 / 异常）**：RTT ≥ 200ms
- 当一方发生静默断网（无 TCP FIN 包的异常掉线）时，服务端心跳检测会在 5 秒内精准识别并更新成员状态为「已掉线」。

### 6.2 断线横幅与重连
- 当网络发生波动或断开时：
  - 界面顶部弹出黄色/红色断线提示横幅（「与房间的连接已断开，正在重连…」）。
  - 大厅就绪与设置操作自动禁用，避免脏操作；保留「离开房间」安全退出入口。
  - 客户端启动指数退避自动重连机制（初始 500ms，按 1.5 倍递增，上限 10 秒）。
  - 横幅上提供 ≥44px 触控区域的手动「立即重连」按钮，方便用户即时尝试。
- **重连恢复**：
  - 客人端凭借握手分配的 `resumeToken` 恢复原始席位，避免被当成重复加入的陌生人。
  - 开局前重连会恢复成员身份并清除就绪状态；开局后重连会保持同一份冻结开局快照，不会触发重新随机分先。
  - 重连成功后横幅自动隐藏，并展示 3 秒轻量绿色 toast（「已重新连接 ✓」）。

### 6.3 房间关闭与退出
- 房主显式解散房间时需进行二次确认。
- 解散后服务端广播 `room.closed` 消息并释放全部资源与端口占用；客人端收到通知后平滑返回加入页面，原输入框保留房间地址以备查验。

## 7. 常见网络排查与防火墙设置

| 现象 | 可能原因 | 解决方法 |
| --- | --- | --- |
| 客人提示「连接超时」或无法打开网页 | 防火墙拦截入站连接 | **macOS**：系统设置 → 网络 → 防火墙，确保放行 Node 进程，或在弹出的授权框选择「允许」。<br>**Windows**：Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙，勾选 Node.js 的「专用网络」和「公用网络」入站权限；或增加入站规则放行实际房间端口（如 8080–8100 TCP）。 |
| 客人提示「连接超时」且 Ping 不通房主 IP | 路由器启用了 AP 隔离或处于不同 VLAN | 很多公共 Wi-Fi、校园网或路由器「访客网络」开启了 **AP 隔离（AP Isolation）**，禁止无线设备互相通信。请切换到家庭普通 Wi-Fi，或使用手机开启热点，双方共同连入热点网络。 |
| 界面仅显示 `127.0.0.1` 回环地址 | 房主设备未连接任何局域网 | 连接 Wi-Fi 或插上网线后再启动程序。回环地址仅用于本机开发测试，跨设备无法访问。 |
| 多网卡机器客人连不上 | 默认选中的 IP 属于虚拟网卡 | 某些虚拟机（VMware/VirtualBox）或 VPN（如 WSL/Tailscale/ZeroTier）会创建虚拟网卡。房主请点击「候选地址列表」，换用 `192.168.x.x` 或 `10.x.x.x` 等路由器分配的真实局域网 IP。 |
| 房主提示端口被占用或连续顺延 | 本地其他服务占用了端口 | 在主菜单「设置」中更改建房优先端口（如改用 `18080`），或通过 `--room-port 18080` 启动。 |
