# 局域网联机搭建指南

本文档介绍如何在局域网（Wi-Fi 或有线网络）环境下搭建并使用翻牌中国象棋的联机大厅。

> **当前阶段能力说明**：交付**局域网联机对战全流程闭环**（建房、地址分享、客人直连、大厅设置同步、双端就绪门禁、冻结开局参数快照、实时走棋、视角自适应、服务端权威局时/步时、1.5 秒将军提示、90 秒断线宽限期保护、权威终局判定与结算弹层、再来一局与返回大厅流转）。同时完整保留单机本地双人对战模式。

---

## 1. 运行前提

- **房主设备**：需要安装 Node.js（推荐 Node.js v18 及以上，已在 v24.x 验证通过）及 npm。
- **客人设备**：**无需安装 Node 或任何开发环境**，只需具备现代桌面或移动端浏览器（Chrome、Edge、Safari、Firefox 等）。
- **网络环境**：两台设备必须连接到同一个局域网（如连接同一个家庭/办公室 Wi-Fi 路由器，或同一台交换机）。

---

## 2. 启动服务（房主）

### 2.1 开发形态启动

适用于代码调试或快速试玩，内置 Vite 模块热更新：

```bash
npm install
npm run dev
```

终端将打印房主控制台地址（默认 `http://127.0.0.1:5173/`）。

### 2.2 生产形态启动（推荐）

经过完整打包构建，响应更轻量稳定：

```bash
npm run build
npm start -- --port 4173
```

终端将打印房主控制台地址（默认 `http://127.0.0.1:4173/`）。

## 3. 端口与网络架构说明

翻牌中国象棋采用安全分层的网络设计：

```
+-------------------------------------------------------------+
| 房主设备 (Host)                                             |
|                                                             |
|  [房主浏览器] ----(仅回环 loopback)----> [Node 控制台进程]   |
|                                           (5173 / 4173)     |
|                                                 |           |
|                                           [按需启动房间服务] |
|                                           (默认 8080 端口)   |
|                                                 |           |
+-------------------------------------------------|-----------+
                                                  |
                                                  | 局域网 HTTP + WebSocket (/ws)
                                                  v
                                      +-----------------------+
                                      | 客人设备 (Guest)       |
                                      | [客人普通浏览器]       |
                                      +-----------------------+
```

### 3.1 房主控制台端口（Loopback）
- **开发端口**：`5173`
- **生产端口**：`4173`
- **安全约束**：控制台仅绑定在 `127.0.0.1`（本机回环接口），不向局域网暴露控制 API，杜绝外部未经授权的房间管理操作。

### 3.2 局域网房间端口（Room Port）
- **默认端口**：`8080`
- **按需监听**：房主在控制台点击「创建房间」后，Node 服务才会真正监听该端口；解散房间后端口立即释放。
- **自动顺延策略**：若 `8080` 端口被其他软件占用，服务会自动尝试 `8081`、`8082` 等顺延端口（最多尝试 20 个端口），直到找到可用端口或耗尽尝试；控制台界面会如实展示当前真正监听的端口号。
- **单端口复用**：客人通过同一个房间端口访问：
  - HTTP 页面：`http://<房主IP>:<房间端口>/`
  - WebSocket 握手：`ws://<房主IP>:<房间端口>/ws`
  无需为 WebSocket 额外开放第二端口。

### 3.3 端口配置方式
房主可通过三种等价方式自定义建房优先端口：
1. **界面配置**：在主菜单「设置」中填写优先端口（1–65535）并保存，本地浏览器会自动记忆。
2. **命令行参数**：启动时指定 `--room-port <端口号>`，例如 `npm start -- --room-port 9000`。
3. **环境变量**：通过 `ROOM_PORT=<端口号>` 指定，例如 `ROOM_PORT=9000 npm run dev`。

### 3.4 权威会话核心与传输适配（RoomSession）
房间的权威状态不绑定任何监听端口，便于后续在线多房间复用同一规则核心：

- **权威会话（`server/room-session.ts`）**：持有大厅、对局、计时、协商、快捷短语、成员与恢复凭据等全部权威状态，负责当前连接归属校验与领域定时器（对局时钟、协商时限、旁观恢复窗口）。会话只面向一个最小连接端口（不透明 connectionId + 发送 + 关闭），可直接构造与销毁，不需要创建任何监听器。
- **LAN 适配器（`server/room-server.ts`）**：负责真实 WebSocket、编解码与协议校验、握手超时、心跳探测、端口顺延与静态页面，把每条传输连接接入会话。房间关闭时由会话广播 `room.closed` 并关闭连接，适配器释放 TCP/WS 监听端口。
- **身份分层（`server/room-identity.ts`）**：用户身份、房间成员席位（host/guest/spectator）、连接标识三者相互独立。身份由服务端生成或可信解析（当前为匿名身份，账号接入通过身份解析器预留，客户端自报的身份一律不采信）；重连时保持身份与席位、仅替换连接，旧连接的迟到消息与关闭回调不会影响新连接。
- **广播边界**：对局与大厅广播只投递给已完成握手且未被替换的当前连接，握手未完成的连接不接收对局广播。

## 4. 建房与客人加入流程

### 4.1 房主操作
1. 本机浏览器打开控制台（`http://127.0.0.1:4173/` 或 `5173`）。
2. 点击「创建房间」。
3. 界面会显示当前房间的专属连接卡片（格式为 `IP:端口`）：
   - 点击「复制」按钮复制连接地址。
   - 若房主机器有多个网卡（例如同时开启了 Wi-Fi、有线以太网或虚拟网卡），可展开「候选地址列表」，选择与客人处于同一网段的局域网 IP。
4. 将复制的地址发送给对手。

### 4.2 客人操作
客人只需使用浏览器，任选以下一种方式进入：
- **方式 A（直链访问）**：在浏览器地址栏直接输入房主分享的 `http://<IP>:<端口>`，页面加载后点「加入房间」即可。
- **方式 B（输入框填入）**：打开已有客户端页面，点击「加入房间」，输入房主提供的 `IP:端口`（支持自动去除首尾空格及自动补全 `http://`），点击「连接」。
- 加入成功后，该地址会自动加入客人的「最近房间」列表（本地保存最多 5 条），后续可一键快捷填入。

## 5. 大厅交互与开局状态流转

1. **设置同步**：
   - 房主可调整「分先策略」（随机抽签、房主执红、客人执红）与「局时模式」（不计时、快棋 10 分+30 秒、标准局 20 分+60 秒）。
   - 客人端实时同步显示设置变更，客人端设置区域保持只读，确保房间规则权威统一。
   - 房主可点击「锁定设置」防止意外误触，锁定期间不可调整参数。
2. **双端就绪门禁**：
   - 双方需各自点击「准备」按钮。
   - 任何一方修改设置或解锁设置，系统会自动重置双方的就绪状态，防止规则不一致下的抢跑。
   - 仅在双方均处于「已准备」状态时，房主的「开始对局」按钮才会点亮。未就绪时点击将被拦截并提示。
3. **冻结开局快照**：
   - 房主点击「开始对局」后，房间状态流转为已开局，大厅设置与操作入口冻结。
   - 若设置了随机分先，服务端在此刻权威抽取红黑归属（不可重复抽取），生成不可变开局参数快照（含设置版本、红黑归属及局时规则）。
   - 双端界面同步呈现快照信息，确保开局状态一致可信。

## 6. 网络状态监控与断线恢复

### 6.1 实时心跳与状态指示灯
- 双端通过 WebSocket 建立 2 秒一次的双向心跳探测（`ping` / `pong`），实时测算往返时延（RTT）。
- 顶部导航栏展示网络状态指示灯与 RTT 数值：
  - **绿色（良好）**：RTT ≤ 80ms
  - **黄色（较高延迟）**：80ms < RTT < 200ms
  - **红色（高延迟 / 异常）**：RTT ≥ 200ms
- 当一方发生静默断网（无 TCP FIN 包的异常掉线）时，每次心跳等待应答 2 秒；前台计时器正常运行时，通常在最后一次应答后约 2–4 秒识别失联并更新成员状态为「已掉线」。浏览器后台节流或设备休眠可能延后检测。

### 6.2 断线横幅与重连
- 当网络发生波动或断开时：
  - 界面顶部弹出黄色/红色断线提示横幅（「与房间的连接已断开，正在重连…」）。
  - 大厅就绪与设置操作自动禁用，避免脏操作；保留「离开房间」安全退出入口。
  - 客户端启动指数退避自动重连机制（退避基准 500/1000/2000/4000ms，每次取基准的 80–100% 随机延迟以分散重试；大厅预算 20 秒，局内预算至少 95 秒，覆盖 90 秒断线宽限期及快照接收）。
  - 横幅上提供 ≥44px 触控区域的手动「立即重连」按钮，方便用户即时尝试。
- **重连恢复**：
  - 客人端凭借握手分配的 `resumeToken` 恢复原始席位，避免被当成重复加入的陌生人。
  - 开局前重连会恢复成员身份并清除就绪状态；开局后重连会保持同一份冻结开局快照，不会触发重新随机分先。
  - 重连成功后横幅自动隐藏，并展示 3 秒轻量绿色 toast（「已重新连接 ✓」）。

### 6.3 弱网下的状态恢复

- 动作提交后棋盘保持最后确认局面并显示等待态；3 秒仍未收到结果时，请求权威快照。被拒绝或未送达的动作不会改变棋盘，也不会自动重发，避免重复走棋。
- 同步请求合并为一个在途请求；3 秒未收到快照即进入原有断线重连流程。手动「立即重连」与自动重连共用当前握手，连续点击不会创建并行连接。
- 局内每 5 秒核对一次权威快照，包含已结束的对局。只漏掉协商完成或最终结算、但心跳仍畅通时，也能恢复到相同结果。收到比棋盘更新的时钟版本时立即请求同步。
- 客户端只接收公开棋局：未翻开的棋子仅下发位置与本局不透明标识，种子、完整开局帧、撤销栈与内部棋子 ID 都不进入线协议；翻牌结果、合法性、计时与胜负由服务端裁决，落点提示也由服务端计算。
- 所有棋局下发路径（welcome 加入/重连、开局与动作广播、重复请求应答、显式同步、拒绝与结算）共用同一份公开快照；广播只投递给已完成握手且属于本房间的连接。
- 旧版本快照、旧时钟采样、旧连接的迟到响应和不属于当前请求的动作拒绝均不会回退已确认局面；更高版本的合法悔棋仍可降低步数。
- 玩家在协商中掉线会取消协商并单独进入断线暂停；恢复后计时继续，协商和断线暂停期间均不扣局时。旁观者掉线不取消协商。
- 恢复只应用当前快照，不补播历史动作音效或翻牌动画。有限故障解除后的收敛依赖宿主仍在运行，长期失联按 90 秒宽限与服务端权威结算处理。
- 可重复故障注入与验证方法见 [v0.9.0 版本说明](releases/v0.9.0.md)。

### 6.4 房间关闭与退出
- 房主显式解散房间时需进行二次确认。
- 解散后服务端广播 `room.closed` 消息并释放全部资源与端口占用；客人端收到通知后平滑返回加入页面，原输入框保留房间地址以备查验。

## 7. 回合计时、90 秒断线宽限期与权威终局结算

### 7.1 服务端权威计时与两端同步
- **时钟档位**：支持「标准局」（1200 秒局时 + 60 秒步时）、「快棋」（600 秒局时 + 30 秒步时）与「不计时」。
- **权威维护与广播**：服务端以 1Hz 频率权威广播 `game.clock` 快照，客户端结合 NTP 时间偏移补偿驱动 100ms 频率平滑毫秒插值走秒。
- **紧迫视觉反馈**：
  - 行动方局时剩余 < 1 分钟时，时钟呈现红色脉动警告（`.urgent-warning`）；
  - 行动方步时最后 5 秒时，步时数字与进度环进入逐秒闪烁高亮（`.extreme-warning`）；
  - 对局暂停或终局时立即停止紧迫动画。
- **将军提示**：当任意一方被将军时，棋盘外框闪烁警示波纹，并居中弹出持续 1.5 秒的「将军！」提示条。

### 7.2 90 秒断线宽限期机制
- 对局进行中若任一方掉线，服务端立即权威冻结主对局时钟与步时，启动 90 秒宽限期倒计时；
- 在线端棋盘上方弹出黄色宽限提示条（显示掉线方角色及权威剩余秒数），时钟显示「已暂停」徽标；
- **宽限期内重连**：掉线方在 90 秒内重新连回后，服务端校验席位并取消宽限截止，恢复对局与时钟走秒；
- **宽限期耗尽**：若掉线方 90 秒内未恢复连接，服务端即时裁定掉线方「掉线超过 90 秒超时判负」，杜绝拔线拖局。

### 7.3 权威终局判定与流转
- **终局触发**：绝杀、将死、吃掉对方将/帅、局时耗尽、单步超时或断线超时，均由服务端权威判定并广播 `game.state` 终局结算数据。
- **终局弹层**：
  - 双方棋盘立即定格，弹出无障碍 `GameResultDialog` 弹层；
  - 准确展示胜利/惜败标题、权威判负原因、红黑双方累计用时与总局时统计；
  - 胜方明子存活棋子播放轻微庆祝动效（支持 `prefers-reduced-motion` 静止适配）。
- **再来一局与返回大厅**：
  - 弹层提供「再来一局」与「返回大厅」按钮；
  - 双方同步权威回退到原房间大厅，清空旧局快照；
  - 点「再来一局」者自动设为已就绪，仍遵守双方均就绪且房主点击开始门禁；点「返回大厅」者停在未准备态。

## 8. 对弈协商流（悔棋、求和与认输机制）

联机对战提供完备的双向协商与终局流转能力，保证状态机时序严密性与防死锁：

### 8.1 悔棋协商流
- **发起条件**：仅在棋局已发生有效走子（步数 > 0）、当前无进行中的协商且连接正常时可发起。
- **互斥锁定与时钟暂停**：发起后，服务端权威暂停对局时钟，双方棋盘与落子操作即刻锁定（`.board.is-disabled`）。
- **30 秒倒计时模态窗**：
  - 发起方展示等待状态；
  - 应答方弹出包含 30 秒动态进度条与剩余秒数倒计时的决策弹层，提供「同意」与「拒绝」选项；
  - 若 30 秒内未应答，服务端按超时自动拒绝处理，防止拖延。
- **准确回退 1 步**：应答方同意后，双方棋盘严格同步回退 1 步，恢复走棋前暗子/明子布局与被吃棋子，时钟精准回滚至行动前检查点并恢复计时。

### 8.2 求和协商流与冷却限制
- **双向求和**：双方均可在对局中发起求和申请，应答方可选择同意或拒绝。
- **10 秒拒绝冷却限制**：若对方拒绝求和，发起方即刻进入 10 秒冷却期（求和按钮显示动态倒计时如 `求和 (10s)` 并禁用），有效防止恶意刷屏骚扰对手。
- **协商平局终局**：对方同意和棋后，服务端立即权威判定终局并广播结算快照，双方弹出终局弹层，展示「平局」与「和」字勋章，终局原因标注为「双方握手言和，协商平局」。

### 8.3 认输确认流
- **防误触二次确认**：点击「认输」时弹出本地确认弹窗，明确提示「认输后对方将立即获胜，本局将以失败定格」，需二次确认。
- **即时权威终局**：确认后立即向服务端提交认输申请，服务端即刻判定对方获胜、己方惜败，广播终局并记录双方用时。

### 8.4 事件通知小条与异常解挂防护
- **3 秒事件轻量提示**：对弈界面上方提供无障碍 `role="status"` 的 3 秒自动淡出通知条，如实呈现协商发起、同意、拒绝、冷却与认输事件。
- **异常断线安全解挂**：协商期间若任一方意外掉线或关闭网页，服务端即刻清除协商定时器并广播 `negotiation-cancelled` 取消事件，棋盘自动解挂解锁，在线方转入 90 秒断线等待宽限期，杜绝对局死锁挂起。

### 8.5 局内内置快捷短语互动
- **12 条内置精选短语**：点击底栏「短语」展开面板，提供问候（如“你好，很高兴和你对弈！”）、赞赏（如“好棋！”、“佩服佩服！”）、思考（如“容我深思熟虑一番”）与终局礼仪（如“承让承让！”、“青山不改，绿水长流，后会有期！”）等 12 条内置短语。
- **5 秒权威频控与冷却倒计时**：发送短语后立即进入 5 秒频控期，按钮显示剩余秒数（如 `短语 (5s)`）并禁用，彻底防止刷屏；服务端权威限流保障通信秩序。
- **3 秒气泡浮层与平滑淡出**：双端各自在自身或对手信息条侧上方弹出对话气泡，居留 3 秒后平滑淡出。
- **无障碍与触控保障**：操作触控区均 $\ge 44\times 44\text{px}$，支持键盘 Esc 快速收起与焦点恢复，并支持 `prefers-reduced-motion` 降级。

## 9. 常见网络排查与防火墙设置

| 现象 | 可能原因 | 解决方法 |
| --- | --- | --- |
| 客人提示「连接超时」或无法打开网页 | 防火墙拦截入站连接 | **macOS**：系统设置 → 网络 → 防火墙，确保放行 Node 进程，或在弹出的授权框选择「允许」。<br>**Windows**：Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙，勾选 Node.js 的「专用网络」和「公用网络」入站权限；或增加入站规则放行实际房间端口（如 8080–8100 TCP）。 |
| 客人提示「连接超时」且 Ping 不通房主 IP | 路由器启用了 AP 隔离或处于不同 VLAN | 很多公共 Wi-Fi、校园网或路由器「访客网络」开启了 **AP 隔离（AP Isolation）**，禁止无线设备互相通信。请切换到家庭普通 Wi-Fi，或使用手机开启热点，双方共同连入热点网络。 |
| 界面仅显示 `127.0.0.1` 回环地址 | 房主设备未连接任何局域网 | 连接 Wi-Fi 或插上网线后再启动程序。回环地址仅用于本机开发测试，跨设备无法访问。 |
| 多网卡机器客人连不上 | 默认选中的 IP 属于虚拟网卡 | 某些虚拟机（VMware/VirtualBox）或 VPN（如 WSL/Tailscale/ZeroTier）会创建虚拟网卡。房主请点击「候选地址列表」，换用 `192.168.x.x` 或 `10.x.x.x` 等路由器分配的真实局域网 IP。 |
| 房主提示端口被占用或连续顺延 | 本地其他服务占用了端口 | 在主菜单「设置」中更改建房优先端口（如改用 `18080`），或通过 `--room-port 18080` 启动。 |

## 10. 旁观模式（围观一盘棋）

房间除两位执色玩家外，还支持多名只读旁观者实时观看对局，适合「一人下、众人看」的桌游社交场景。

### 10.1 加入方式

- **自动旁观**：两位玩家席位已满、或对局已经开始后，「加入」会自动以旁观身份进入房间，不再提示房间已满。
- **显式旁观**：在加入页面点「旁观观战」，直接以旁观身份进入，任何时候都不占执色席位。
- 旁观者不参与准备就绪流程，也不影响「双方准备后由房主开始对局」的开局门禁。

### 10.2 只读约束

- 旁观端隐藏并禁用一切操作入口：翻牌、走子、悔棋、求和、认输、快捷短语发送（双方已发出的短语仍可观看）、设置/准备/开局入口。
- 协议层同样只读：旁观者的对局动作、协商、认输、快捷短语与大厅命令消息一律被服务端拒绝（各自通道给出非致命拒绝应答），不会改动步数、局面、计时、协商与结算，也不会断开旁观连接。
- 协商进行中，旁观端显示中立只读的协商提示，无任何回应按钮。

### 10.3 局面同步

- 旁观端接收与玩家完全一致的权威广播：开局种子初始化、翻牌、走子、吃子、回合切换、将军提示、协商通知、计时采样与终局结算。
- 对局进行中加入时，握手 welcome 直接携带权威快照（棋盘明暗、最近一步轨迹、步数、回合、计时），立即追上当前局面，随后增量跟进，无「从头回放」等待。
- 旁观视角固定红方在下，双方以红/黑标签展示；结算弹层显示胜方与原因（平局显示平局），不提供「再来一局」「返回大厅」等发送入口，可本地收起结果或「离开观看」。

### 10.4 断线重连

- 旁观者持有独立的恢复凭据：掉线后在恢复窗口内重连，自动恢复旁观身份并同步当前局面，不从头回放、不补播历史动画与音效。
- 旁观者掉线不影响对局：时钟照常走动、协商不被取消；其记录保留到恢复窗口结束，之后自动清理。
- 恢复凭据不可跨身份使用：旁观凭据不能登录玩家席位，玩家凭据也不能冒充旁观者。

### 10.5 名单、人数与退出

- 大厅与对局内均展示旁观者名单与在线旁观人数（在线数只计当前在线成员），两位玩家与旁观名单分区展示。
- 「最近房间」列表会展示各房间的只读人数摘要（阶段、玩家数、旁观数）；房间不可达时明确标注「人数未知」，不伪造数字。
- 旁观者可随时点「离开观看」主动退出；房主关闭房间时，所有旁观端会收到明确的解散提示并回到加入页面。

### 10.6 版本要求

旁观端与玩家端必须运行相同版本：协议版本不一致时会给出「双方版本不一致，请升级到相同版本后重试」的提示，请刷新页面或同步升级后重新加入。
