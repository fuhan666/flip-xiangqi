# 翻牌中国象棋开发分阶段规划

当前版本为 **0.9.0**，已交付本地双人、局域网实时对战、音效反馈、只读旁观、棋谱导出与复盘，以及弱网状态恢复。发布事实见 [v0.9.0 版本说明](releases/v0.9.0.md)。第 1–9 节保留最初 MVP 的阶段拆分，后续版本章节记录各版本发布时的范围。

## 1. 规划目标

本规划用于把首版产品拆成可连续交付的阶段。每个阶段都应形成清晰的产出物，且尽量以前一阶段的结果作为下一阶段输入，避免过早引入联网、AI 或复杂外围系统。

当前目标固定为：先完成本地双人 MVP，让规则闭环、可玩、可验证。

## 2. 阶段总览

| 阶段 | 名称 | 目标 |
| --- | --- | --- |
| Phase 1 | 规则建模与项目骨架 | 建立棋盘、棋子、局面状态与基础工程结构 |
| Phase 2 | 开局生成与回合状态机 | 完成随机暗置开局、翻牌动作、回合切换 |
| Phase 3 | 走法校验与吃子规则 | 完成明子走法、暗子阻挡、不可直接吃暗子等核心规则 |
| Phase 4 | 将军判定与终局结算 | 完成将军、照将、非法着法拦截与胜负判定 |
| Phase 5 | 本地双人交互与体验补全 | 做出可完整游玩的本地双人 MVP 界面和基础信息反馈 |

## 3. Phase 1: 规则建模与项目骨架

### 目标

- 明确前端技术方案和基础目录结构
- 建立棋盘坐标、棋子实体、阵营、明暗状态的数据模型
- 预留规则引擎与 UI 表现层的边界

### 主要交付物

- 项目初始化完成，可本地运行
- 棋盘与棋子核心数据结构
- 基础局面状态容器
- 开发文档或注释，说明核心模型字段含义

### 完成标准

- 代码中可以稳定表达 9x10 棋盘占用关系
- 每枚棋子具备唯一身份、阵营、棋种、坐标、明暗状态
- 规则计算层与界面层不直接耦合

## 4. Phase 2: 开局生成与回合状态机

### 目标

- 实现“将/帅明置，其他棋子全局随机暗置”的开局生成逻辑
- 实现翻牌算一步的状态流转
- 实现当前行动方、一步完成后的回合切换和合法动作入口

### 主要交付物

- 随机开局生成器
- 翻牌动作处理逻辑
- 回合状态机
- 可用于开发调试的初始局面展示

### 完成标准

- 每次新开局都满足规则限定的格位集合
- 翻开任意暗子后会正确暴露真实棋子信息
- 翻牌不会附带移动或吃子
- 回合在翻牌后正确切换

## 5. Phase 3: 走法校验与吃子规则

### 目标

- 实现所有明子的标准中国象棋走法
- 将暗子纳入阻挡和目标合法性判定
- 实现只能吃对方明子、不能直接吃暗子的规则

### 主要交付物

- 各棋种合法移动与吃子校验
- 路径阻挡判定
- 炮的特殊吃子逻辑
- 非法操作返回明确错误原因

### 完成标准

- 车、马、炮、相/象、士/仕、兵/卒、将/帅的走法全部可验证
- 暗子会阻挡车、炮和将/帅照面的路径
- 任何棋子都不能直接吃未翻开的暗子
- 炮在“有架子但目标为暗子”的情况下会被正确拦截

## 6. Phase 4: 将军判定与终局结算

### 目标

- 实现将军判定
- 拦截让己方将/帅暴露在攻击下的非法着法
- 处理照将和基础终局判定

### 主要交付物

- 将军检测逻辑
- 应将校验逻辑
- 照将检测
- 将死判定和对局结束状态

### 完成标准

- 任意一步执行后都能重新计算双方是否处于将军状态
- 行棋方无法提交让己方将/帅处于非法被将状态的动作
- 将/帅直接照面会被识别为非法局面
- 被将且无合法着法时能正确结算胜负

## 7. Phase 5: 本地双人交互与体验补全

### 目标

- 做出可完整游玩的本地双人界面
- 增加玩家操作反馈，降低规则理解成本
- 提供首版必要的体验补全能力

### 主要交付物

- 可点击翻牌、选子、落子的棋盘界面
- 当前回合提示、将军提示、非法操作提示
- 重新开局能力
- 吃子区或基础对局信息面板

### 完成标准

- 两位玩家能在同一设备上完成一整局游戏
- 非法操作会有明确反馈，不需要依赖控制台排查
- 对局结束后能显示胜负结果并支持重新开局

## 8. 建议实施顺序

1. 先把规则模型和局面状态表达清楚，再谈交互
2. 先把翻牌与回合跑通，再补完整走法和终局
3. 在规则引擎稳定后补 UI 提示、吃子区和重新开局

## 9. 暂不进入本轮计划

以下内容不进入当前阶段拆分：

- 联网走棋对局
- AI 对手
- 匹配系统
- 账号体系
- 复杂复盘与棋谱导出
- 大量视觉特效和高级动画

## v0.9 发布范围

- 分层动作音效、音量与静音设置、首次手势解锁及 reduced-motion 兼容。
- 局域网只读旁观、中途快照加入、独立身份恢复与终局观看。
- 完整中文文本与 JSON 棋谱导出、载入校验和只读逐步复盘。
- 弱网故障注入、动作与同步的有界恢复、时钟及旧响应过滤、协商断线后恢复计时、重连抖动与握手合并。
- 当前传输使用局域网宿主与协议 6；网络参数和验证方法以版本说明为准。

## 10. v0.8 发布收口状态

### 当前状态

- v0.8 交付局域网联机实时对战、快捷短语互动与棋谱记录底座版本，发布事实记录于 [v0.8.0 版本说明](releases/v0.8.0.md)
- 交付端到端局域网实时走棋、红黑视角自适应映射与坐标投影逆映射、服务端权威规则与行棋仲裁
- 交付服务端权威计时（标准局、快棋、慢棋、不计时）、1Hz 平滑走秒广播、读秒脉动预警、90 秒断线宽限保护期与重连无缝恢复
- 交付 12 条内置快捷短语面板、5 秒权威共享频控倒计时、3 秒浮动气泡平滑淡出及 reduced-motion 降级
- 交付局中悔棋/认输/求和双向协商流（30 秒应答倒计时弹窗、行棋互斥锁定、悔棋单步时钟回滚、求和 10 秒冷却）
- 交付棋谱记录基础设施（连续 stepNumber 步数、flip/move/capture 分类、吃子快照、有效思考时间 durationSeconds 权威注入及独立的 matchEvents 协商留痕轨迹）
- 走查 1366×768、1920×1080、683×768 多分辨率响应式布局，严格保障 `scrollWidth <= clientWidth` 无水平溢出
- 33 个单元测试文件（273 个测试）与全量 Playwright E2E 套件 100% 通过

### v0.8 已完成范围

- 局域网实时走棋、翻牌、吃子、将军与胜负判定
- 双方视角自适应（己方棋子均居下方正向操作）
- 权威时钟与 90 秒断线保护期
- 12 条内置快捷短语互动面板与气泡展示
- 悔棋/求和/认输协商流
- 结构化动作历史与权威耗时注入
- 响应式多视口适配与全量自动化回归

### v0.8 明确不含

- 棋谱文件导出（PGN/JSON）与对局回放器界面（规划于 v0.9）
- 公网中继、云端自动撮合或账号社交体系
- 单机 AI 算法对战
