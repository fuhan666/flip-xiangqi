# 长局历史存储与动作耗时

本页记录「一份有效历史 + 紧凑撤销 + 独立开局」改造前后的可复核微基准。它衡量的是**存储结构与单步动作成本**，不代表在线房间容量、网络吞吐或浏览器渲染性能。

## 采样条件

- 前后两侧使用**同一个** `scripts/benchmark-history-worker.mjs` 与同一段驱动参数，只切换源码目录；旧实现取改造前 `main` 的提交，新实现取本次交付代码。
- 测试局面：32 枚全部明置的标准开局，双方马在 (1,9)/(1,0) 做四步往返循环；全程无吃子、无终局，每步校验动作成功且历史步数 +1。
- 规模：100 / 200 / 400 / 1000 步；每个规模 3 次完整重复，取中位数。
- 每个采样点在独立 Node 子进程中顺序执行：`--expose-gc --max-old-space-size=2048`，单点上限 120 秒；先跑 20 步独立短局预热并释放，再初始化采样局。
- 采样局只保留最新 `GameState`；不保留历史帧，也不把 JSON 序列化计入动作耗时。计时用 `performance.now()`，预分配 `Float64Array` 记录每步耗时。
- 堆占用：采样局初始与 N 步后各显式 GC 两次，读取 `process.memoryUsage().heapUsed`，报告净增 MiB。`historyJSONBytes` 在计时区外对 `actionHistory + undoStack` 做一次 JSON 序列化，仅作存储结构对照，不计入耗时。
- 采集环境：macOS (darwin) arm64，Apple M1 Pro 8 核，16 GiB 内存，Node v24.13.0，采集时间 2026-10-21T06:21:10Z。

## 复现命令

```bash
# 旧实现：在被测提交上创建只读工作树
git worktree add --detach ../history-baseline <改造前 SHA>

# 前：旧实现
node scripts/benchmark-history.mjs --source-root ../history-baseline --label before \
  --steps 100,200,400,1000 --repeats 3 --heap-mb 2048 --timeout-ms 120000 \
  --output ../history-before.json

# 后：本次交付
node scripts/benchmark-history.mjs --source-root . --label after \
  --steps 100,200,400,1000 --repeats 3 --heap-mb 2048 --timeout-ms 120000 \
  --output ../history-after.json
```

两个驱动参数完全一致，未把新实现逻辑移植到旧基线。脚本对每个样本点启动独立子进程，超时会记录目标步数、实际完成步数、退出码/信号与 elapsed，不会外推数值。

## 解读

- 旧实现每个撤销点保存完整 `GameStateSnapshot`，其中又嵌入当时的整段 `actionHistory`；步数增长时保留空间按平方级增长：100 → 1000 步堆净增放大约 78 倍（步数放大 10 倍），每步堆净增从 24.5 KiB 升到 191.1 KiB。
- 新实现每步只保留一条紧凑撤销记录（最多两枚棋子的旧值 + 标量 + 历史长度），历史只有一份权威副本；100 → 1000 步堆净增 0.17 → 0.82 MiB，每步净增稳定在 1 KiB 量级，近似线性。
- 累计动作耗时：旧实现每次动作深拷贝历史与整个撤销栈，1000 步约 101.5 秒；新实现只复制 32 枚棋子的局面数据，约 20.9 毫秒，且单步均值随步数下降（不含历史复制）。
- 固定开销主要来自模块/JS 运行时初始化与首个采样局，约 0.1–0.2 MiB；GC 波动会让小规模点的每步净增略高。
- 上述结论只适用于规则引擎的存储与动作路径。浏览器渲染、网络广播、房间容量仍由各自验证覆盖。

## 行为验证

- `src/game/__tests__/history-storage.test.ts`：400 步后撤销记录键集合固定、最多两枚棋子；200→400 步整体序列化体积增长低于 2.6 倍；连续撤销 30 步逐步对照棋盘/回合/将军/历史/`recentAction`；撤销后分叉只保留新主线；规则模拟在掺入 5000 条伪造历史/撤销数据时结果不变且不改写输入。
- `src/network/__tests__/match.test.ts`：多步与连续悔棋后开局帧保持不变，时钟检查点与回合一致，已耗思考时间不被返还。
- `src/records/__tests__/record.test.ts`：本地与联机对局导出同一 schema，初始布局完整、有效主线可逐帧复盘。
